# Muzon

Локальный музыкальный плеер для Linux. Основная нативная сборка — Rust/Iced,
GStreamer и SQLite, без WebView, Node.js и Tauri в зависимостях.

```bash
cargo run --locked -p muzon-native -- --profile /tmp/muzon-native
cargo test --locked --workspace
./packaging/native/build.sh release
```

[Описание интерфейса](crates/muzon-native/README.md),
[план и проверки миграции](docs/NATIVE_MIGRATION.md),
[переносимая сборка и импорт профиля](packaging/native/README.md),
[локальный PKGBUILD](packaging/arch/README.md).

Четыре крейта входят в единый Cargo workspace и используют корневой `Cargo.lock`.
Исторический интерфейс React/Tauri сохранён в `src/` и `src-tauri/`, исключён из
workspace и собирается отдельно. Его описание и прежние команды ниже относятся
к старой оболочке. Рабочий профиль автоматически не импортируется.

Собирал под себя, потому что надоели все существующие варианты — либо жрут память,
либо интерфейс из 2007-го, либо просто не то, что хотелось. Получилось примерно
то самое.

## Что умеет

- Библиотека с тегами, обложками, избранным и плейлистами
- Гэплесс и кроссфейд между треками, 10-полосный эквалайзер, тайм-стретч
- Синхронизированные тексты песен (LRC), редактор тайминга прямо в приложении
- Альбомы / исполнители / плейлисты отдельными вкладками
- Поиск по сайдбару + `Ctrl+K` командная палитра
- MPRIS (медиаклавиши, интеграция с DE)
- Таймер сна, хоткеи, темизация (в том числе цвета из темы рабочего стола)
- Зеркало фонотеки в S3-совместимом хранилище

## Облако (S3)

Настройки → «Облако (S3)». Подходит любое хранилище с API S3: AWS, MinIO,
Backblaze B2, Cloudflare R2, Yandex Object Storage. Кнопки-пресеты
подставляют адрес, регион и стиль адресации за вас.

Для Yandex Object Storage: адрес `https://storage.yandexcloud.net`, регион
`ru-central1`, ключи — статический ключ доступа сервисного аккаунта с ролью
`storage.editor`. Совместимость проверена запросом к самому хранилищу: оно
присылает в ответе свой каноничный запрос, и он совпадает с нашим побайтово
(тест `yandex_builds_the_same_canonical_request_as_we_do`).

| Поле | Что писать |
|---|---|
| Бакет | имя бакета |
| Папка в бакете | префикс, по умолчанию `muzon` |
| Адрес | пусто — AWS в указанном регионе; иначе `https://хост:порт` |
| Регион | `us-east-1`, если хранилище регионов не знает |
| Путь вида хост/бакет/ключ | для MinIO и своих серверов включено, для AWS снять |

Ключи доступа уходят в связку ключей системы (`secret-tool`, service `muzon`),
в файлах конфигурации они не хранятся.

Раскладка в бакете:

```text
<префикс>/tracks/<имя папки фонотеки>/<путь внутри неё>
<префикс>/library.json
```

Синхронизация двусторонняя и **никогда ничего не удаляет**: отправляется то,
чего нет в хранилище, скачивается то, чего нет локально. Файлы сравниваются по
размеру. `library.json` хранит избранное, счётчики прослушиваний и плейлисты и
не перезаписывается, а сливается: лайк остаётся лайком с любой машины, счётчик
берётся больший, плейлисты объединяются по имени.

Подпись запросов — SigV4 собственной реализацией (`data/s3/sigv4.rs`), сверена
с эталонным вектором AWS; сам клиент проверяется интеграционным тестом против
заглушки сервера (`tests/fake_s3.py`).

## Стек

Rust + [Tauri v2](https://tauri.app) + GStreamer на бэкенде, React + TypeScript +
Tailwind (shadcn/ui на Base UI) на фронте, SQLite для библиотеки.

## Запуск в разработке

Нужны: Node.js, Rust, GStreamer с плагинами (base/good/bad/ugly), webkit2gtk.

```bash
npm install
npm run tauri dev
```

## Сборка

```bash
npm run tauri build
```

Бинарник и бандлы окажутся в `src-tauri/target/release`.

## Ryoku и другие оболочки

Настройки → «Цвета системы» включает следование палитре рабочего стола.
Выбранный файл показан рядом с переключателем. Приоритет источников:

1. `MUZON_SCHEME_FILE` — явный путь, без автоматической подмены другим файлом.
2. `$XDG_CACHE_HOME/ryoku/colors.json` (по умолчанию `~/.cache/ryoku/colors.json`).
3. `$XDG_STATE_HOME/caelestia/scheme.json`, затем `rice/scheme.json`
   (по умолчанию `~/.local/state`).

Поддерживаются плоская карта Material-ролей Ryoku и объекты `colours` / `colors`.
Цвета — шестизначный RGB или восьмизначный RGBA, с `#` или без. Нужны фон
(`surface` / `background`), `primary` и текст (`onSurface` / `onBackground`).
Недостающие роли дополняются светлой или тёмной темой по яркости фона.
Повреждённая палитра не применяется; последняя рабочая тема остаётся на экране.
Файл можно создать позже или заменить атомарно: изменения подхватываются за две
секунды. В ручном режиме системная палитра не перекрашивает окно; переключение
обратно работает без перезапуска. Собственная тема хранится отдельно.

Штатный media-виджет Ryoku использует `org.mpris.MediaPlayer2.muzon`: метаданные,
обложка, play/pause, next/previous и seek остаются стандартным MPRIS. Выбор плеера
и медиаклавиши принадлежат оболочке, Muzon не перехватывает их у браузера.
`Raise` возвращает окно из трея; `Quit` завершает приложение с сохранением сессии.

Дополнительная панель очереди, избранного и текстов — отдельный PluginKit-плагин
`muzon`. Его единственный редактируемый исходник на этой машине:
`~/Documents/ryoku-plugins/muzon/`; в репозитории приложения второй копии нет.
Установка из исходника (перед обновлением установленной версии выполните
`ryoku plugin remove muzon`):

```bash
ryoku plugin validate ~/Documents/ryoku-plugins/muzon
ryoku plugin add ~/Documents/ryoku-plugins/muzon --bar --yes
```

Открытие — нажатием на значок ноты на QS Bar. Открытие панели не меняет избранное.
При закрытом плеере панель показывает offline-состояние и кнопку запуска;
автоматического запуска нет. Соединение с локальным `control.sock`, подписки и
таймер позиции действуют только при открытой панели. Закрытие и повторное
открытие восстанавливают снимок и подписки; интернет для панели не используется.
Синхронизация строк использует события MPRIS и локальный таймер; изменение темпа
в середине трека пока не передаётся этим socket API.

`Super+Alt+M` оставлен действию визуализатора Ryoku. Публичного глобального IPC
для переключения панели плагина в этой версии нет: панель открывается кликом,
новая горячая клавиша не добавлена. Существующие бинды сохранены.

Удаление только панели: `ryoku plugin remove muzon`. Это не удаляет плеер,
библиотеку или его настройки. Для отключения синхронизации цветов выключите
«Цвета системы». Откат кода выполняется отдельно через git владельцем проекта;
состояние библиотеки менять для этого не нужно. Исходник плагина после удаления
сохраняется в `~/Documents/ryoku-plugins/muzon/`.

# Muzon: нативный интерфейс на Iced

Самостоятельный Rust-плеер без Tauri, WebView и JavaScript. Два режима:
`--demo` с 5000 синтетическими треками и `--profile DIR` с настоящей
библиотекой и воспроизведением через общий `muzon-core`/GStreamer.
Режим и профиль выбираются явно; установленный Muzon автоматически не открывается.

## Запуск

Из корня репозитория:

```bash
cargo run --manifest-path crates/muzon-ui-prototype/Cargo.toml -- --demo
cargo run --manifest-path crates/muzon-ui-prototype/Cargo.toml -- --profile /tmp/muzon-native
```

Для сборки нужны Rust, системные библиотеки GStreamer и плагины декодирования
тех же форматов, что использует основной Muzon. Даже демонстрационный режим
собирается с общей зависимостью на GStreamer. Iced остаётся на ветке 0.13.1;
точные версии зависимостей фиксирует Cargo.lock. Для системного выбора папки
нужны сессионный D-Bus и XDG Desktop Portal с FileChooser-бэкендом.
На Linux диалог использует libdbus; резервный вариант — Zenity.

Профиль содержит `muzon.sqlite3`, `config/session.json`,
`config/playback_settings.json` и кэш `covers/`. Файл `native.lock` блокирует
второй нативный экземпляр с тем же профилем. Не используйте профиль установленного
Tauri-приложения для этого экспериментального интерфейса: блокировка между
разными оболочками не согласована. Добавленные музыкальные файлы читаются,
сканер не меняет их теги и не копирует библиотеку в профиль.

## Реальный режим

- «Выбрать папку…» открывает системный диалог каталогов через XDG Portal;
  выбранная папка сразу добавляется и сканируется. Отмена ничего не меняет.
  Ручной ввод пути и кнопка «Добавить путь» также доступны. «Обновить»
  пересканирует библиотеку. Поиск работает по названию, исполнителю и альбому.
- В строках библиотеки, избранного, подборок и плейлистов показываются обложки
  из тегов или папки. Они загружаются в фоне только для окна видимых строк,
  пакетами до восьми; кэш ограничен 128 элементами. Без обложки видна заглушка.
  На узком окне название и исполнитель объединяются в компактную строку;
  на широком сохраняются отдельные столбцы.
- Клик по треку заменяет очередь текущим результатом поиска и начинает
  воспроизведение. Кнопка `+` добавляет отдельное вхождение в конец очереди.
  Сам поиск не меняет очередь.
- Нижняя панель управляет воспроизведением, остановкой, переходами,
  перемоткой и громкостью. Перемотка применяется при отпускании ползунка.
- Экран очереди показывает активный порядок с текущим треком первым;
  доступны shuffle, repeat (off/all/one), выбор и удаление вхождения.
  Повторяющиеся песни адресуются по позиции, а не только по пути.
- «Сейчас играет» показывает обложку и локальные LRC с подсветкой текущей
  строки. Загрузка медиа выполняется вне потока UI, без сетевых запросов.
- Очередь, shuffle/repeat, громкость и позиция восстанавливаются при запуске
  **на паузе**. Отсутствующие файлы исключаются, курсор пересчитывается.
- При доступном трее закрытие скрывает окно. «Выйти» дожидается остановки ядра,
  фоновых работ и сохранения сессии. При SIGKILL финальное сохранение невозможно.

Интерфейс получает последние снимки состояния каждые 200 мс; библиотека,
очередь и порядок разделяются через Arc и не копируются на каждом тике.
Списки строят окно из 64 строк фиксированной высоты 40 px с распорками:
тысячи невидимых строк не создаются как виджеты. Поиск и смена экрана
сбрасывают скролл. При очень быстром скролле окно может отставать на кадр.

## Альбомы, исполнители и жанры

Разделы группируют общую библиотеку, не меняя играющую очередь. Выбор группы
показывает её треки; «Слушать» заменяет очередь показанным результатом,
«В очередь» добавляет результат в конец. Поиск учитывает название группы и
поля треков. Номера строк разрешаются в исходные индексы библиотеки.

Альбом определяется парой исполнитель/название (без неоднозначного объединения
строк), треки следуют номерам тегов. Дискография исполнителя сортируется по
году, альбому и номеру; неизвестный год идёт последним. «Без жанра» находится
в конце перечня жанров. Порядок названий определяется Unicode без учёта
регистра, а не локализованным браузерным collator. Альбомы представлены адаптивной
сеткой обложек с поиском и отдельной страницей треков. Число колонок меняется
при изменении ширины окна; строятся только ближайшие строки карточек. Обложки
загружаются вне UI-потока пакетами до четырёх; кэш ограничен 256 элементами.
Переход в альбом и возврат к сетке не меняют очередь. Исполнители и жанры
сохраняют списочное представление. Каталог групп пересчитывается при смене
раздела или библиотеки; на обычном тике не пересоздаётся. Оба списка
виртуализированы, включая библиотеки с тысячами групп.

## Редактор тегов и LRC

Кнопка карандаша в строке трека открывает редактор. На вкладке «Теги» доступны
название, исполнитель, альбом, номер трека, жанр, год и путь к новой PNG/JPEG-
обложке. Пустой путь сохраняет прежнюю обложку. Метаданные записываются только
по кнопке «Сохранить», затем обновляются библиотека и все вхождения в очереди;
id, избранное, плейлисты, скорость и счётчик прослушиваний сохраняются.

На вкладке «Текст / LRC» можно редактировать многострочный текст и сохранить
его рядом с аудиофайлом как `.lrc` либо во встроенный тег. Источник определяет
начальное положение переключателя. «Вставить текущее время» вставляет метку
`[mm:ss.xx]` в позицию курсора, если редактируется играющий трек. Рядом доступны
пауза/продолжение. Встроенный синхронный LRC имеет приоритет над sidecar-файлом;
для подсветки строк требуются временные метки.

«Найти в LRCLIB» выполняет запрос только по нажатию. Найденный текст сначала
показывается отдельно: заменить черновик и сохранить файл нужно явно.
Сервис получает название, исполнителя, альбом и длительность выбранного трека.
Учитывается ограничение частоты запросов; поздний ответ закрытого редактора
не изменяет другой трек. В режиме простукивания Space отмечает следующую строку
по позиции текущего трека; доступны отмена последней метки и перенос результата
в черновик. До «Готово» исходный текст не заменяется.

Запись выполняется вне потока UI и аудиотиков, через временный файл с расширением
`.tmp` рядом с оригиналом. После проверки формата и повторного чтения тегов файл
атомарно заменяется; при ошибке до замены оригинал остаётся прежним. Если формат
не сохранил запрошенные поля или встроенный текст, редактор сообщает об этом,
не выдавая успешную запись. Символические ссылки на аудиофайлы сохраняются,
редактируется их цель. Сканирование и редактирование файлов сериализованы.

Изменения обложки и LRC обновляют текущее отображение без переключения песни;
запоздалые результаты старой загрузки медиа отбрасываются. Обложки кэшируются
с учётом наносекундного mtime, включая несколько правок за одну секунду.

Закрытие диалога, Escape и выход из приложения защищают несохранённый черновик:
нужно сохранить или явно отбросить изменения. Во время записи закрытие запрещено.
Ошибка записи оставляет поля и текст в редакторе. Вкладки сохраняются отдельно.
Аудиофайл и БД не являются одной транзакцией: если файл записан, а БД обновить
не удалось, сообщение явно указывает на частичный результат; поможет повторная
запись или пересканирование. Текст ограничен 1 МиБ, новая обложка — 16 МиБ.

## Таймер сна и клавиши

В разделе «Таймер сна» доступны 15/30/45/60/90 минут и остановка после текущего
трека. Таймер ставит воспроизведение на паузу, срабатывает один раз и сбрасывается.
Исполняется аудиоядром даже при скрытом окне. Пауза не приостанавливает обратный
отсчёт; перезапуск приложения таймер не восстанавливает. Режим «после трека»
отключает подготовку следующего и имеет приоритет перед повтором очереди.
Уже начатый кроссфейд может завершить переход, после чего ядро немедленно ставит
воспроизведение на паузу. Активный таймер виден в сайдбаре и в `status.sleep`
сокетного API (`remainingSecs`, `endOfTrack`).

Клавиши внутри окна: пробел — пауза, N/P — следующий/предыдущий трек,
стрелки влево/вправо — перемотка на 5 с, вверх/вниз — громкость на 5%,
Ctrl+F — поиск, Escape — закрыть диалог или вернуться к библиотеке.
Клавиши, занятые полями ввода или ползунками, не управляют воспроизведением.
В разделе «Клавиши» можно переназначить действия одиночными клавишами,
сбросить настройки и повторить сохранение при ошибке. Занятые сочетания
отклоняются. Ctrl+K открывает палитру команд: поиск экранов, треков, групп,
плейлистов и действий; вверх/вниз выбирают результат, Enter выполняет его.
Управление при неактивном окне выполняется через MPRIS и системные медиаклавиши.

## Категории настроек

В сайдбаре один закреплённый пункт «Настройки». Внутри расположены категории
«Звук», «Внешний вид», «Клавиши», «Таймер сна», «Облако» и «Скробблинг».
Палитра Ctrl+K по-прежнему открывает каждую категорию напрямую; команда
«Выбрать папку с музыкой» вызывает тот же системный диалог, что и кнопка библиотеки.

## Настройки звука

Экран «Звук» доступен через «Настройки → Звук» и по кнопке эффектов в нижней панели.
Эквалайзер содержит 10 полос (−24…+12 дБ), пресеты «Плоский», «Бас», «Вокал»,
«Рок» и ручную регулировку. Пресет меняет только EQ. «Сбросить эффекты»
возвращает EQ, кроссфейд и ReplayGain к исходным значениям, сохраняя скорости
отдельных треков.

Кроссфейд задаётся от 0 до 12 секунд; при 0 используется gapless.
ReplayGain поддерживает режимы «Выключено», «Треки» и «Альбомы» и предусиление
от −6 до +12 дБ. Без тегов ReplayGain файлы играют без выравнивания.
Скорость от 0,25× до 4× сохраняется отдельно для каждого трека. При смене
трека состояние перетаскивания ползунка сбрасывается; уже отправленные
изменения адресуются исходному id. Временный Rate через MPRIS не перезаписывает
сохранённую скорость.

Изменения применяются сразу, запись объединяется после 300 мс без ввода;
отпускание ползунка и выход явно сбрасывают оставшиеся изменения.
Клавиатурные изменения тоже сохраняются без отпускания мыши. EQ/кроссфейд/
ReplayGain записываются атомарной заменой `config/playback_settings.json`,
скорости — транзакцией в SQLite. Неудачная запись остаётся несохранённой и
показывается в интерфейсе с возможностью повторной попытки. Если сохранить
параметры при закрытии не удалось, окно остаётся открытым: можно повторить
сохранение или явно выбрать «Закрыть всё равно». Снимки и кэш
скоростей не пересоздают библиотеку и её поисковый индекс на каждом движении.

## Избранное и плейлисты

Сердечко в строке, на экране «Сейчас играет» и в нижней панели отмечает трек
как любимый. Раздел «Избранное» поддерживает поиск, воспроизведение результата
целиком и добавление его в очередь. Изменение через control.sock отражается
в интерфейсе тем же снимком состояния. Во время сохранения сердечко данного
трека временно недоступно, чтобы случайный двойной клик не отменил отметку.

В разделе «Плейлисты» доступны создание, выбор, переименование, удаление с
подтверждением, воспроизведение и добавление содержимого в очередь. Кнопка
«В плейлист» у трека открывает выбор списка; там же можно создать новый список
с этим треком. Повторное добавление не создаёт дубликаты и не меняет прежнюю
позицию — так устроена общая БД Muzon. Кнопки вверх/вниз меняют порядок в полном
плейлисте, даже при активном поиске; крестик убирает трек только из списка.
Перетаскивание пока не реализовано. Диалоги закрываются кнопкой или Escape;
начавшееся удаление не выдаётся за отменённое.

Глобальный поиск фильтрует текущую коллекцию. «Слушать всё» создаёт очередь из
показанного результата в том же порядке. Сам поиск и редактирование плейлиста
не меняют уже играющую очередь. Удаление списка не удаляет музыкальные файлы,
не сбрасывает избранное и не останавливает воспроизведение.

Плейлисты и избранное записываются в существующие таблицы SQLite, без нового
формата хранения. Создание с начальным набором треков и пакетное добавление
выполняются транзакционно. Имена и упорядоченные id публикуются ядром отдельным
Arc-снимком, который не пересобирается на каждом тике. В интерфейсе id
сопоставляются с общей библиотекой; отсутствующие после сканирования треки
исключаются. Список треков, перечень плейлистов и список выбора в диалоге строят
не более 64 строк по 40 px вокруг положения прокрутки.

Умные подборки включают часто прослушиваемые, недавние, забытые,
непрослушанные и недавно добавленные треки. История считается в ядре один раз
на вхождение в очереди после половины трека либо 240 секунд (для треков длиннее
30 секунд). Очередь можно переставлять за ручку или кнопками вверх/вниз:
играющий трек сохраняется, включая перемешанный порядок и повторения.

## Интеграция с рабочим столом

Нативная оболочка публикует MPRIS без Tauri: play/pause/stop, next/previous,
перемотку, громкость, shuffle/repeat, скорость, метаданные и обложку.
Смена состояния объявляется через PropertiesChanged; перемотка — через Seeked.
SetPosition с устаревшим идентификатором трека игнорируется, в том числе при
переходе к другому вхождению того же файла. Raise передаётся окну, Quit проходит
через обычное сохранение сессии и завершение. OpenUri принимает только локальные
файлы, уже присутствующие в библиотеке данного профиля.

По умолчанию D-Bus-имя — `org.mpris.MediaPlayer2.muzon.native.instance<PID>`:
разные профили и старая версия могут работать рядом. Переменная
`MUZON_MPRIS_NAME=muzon` задаёт суффикс после `org.mpris.MediaPlayer2.`;
пустое значение отключает MPRIS. Отсутствие D-Bus или занятое имя не останавливает
плеер: причина выводится в stderr. Имя процесса не заменяет регистрацию desktop-файла
при будущей установке нативного приложения.

Сокет по умолчанию находится в `<профиль>/control.sock`, чтобы экспериментальный
плеер не подменял сокет установленного Muzon. `MUZON_CONTROL_SOCKET` задаёт другой
путь, например `$XDG_RUNTIME_DIR/muzon/control.sock`, когда нативная версия станет
основной. Права сокета — 0600; активный сокет другого процесса и обычные файлы
не заменяются. Lock-файл рядом с сокетом остаётся после выхода и может использоваться
повторно; сам сокет удаляется при корректном завершении.

Протокол совместим с Tauri: NDJSON-запросы с `id`, `method`, `params`, ответы
с `result` или `error`. Методы: `status`, `queue` (before/after), `queue.play`
(index — исходная позиция очереди), `favorite.toggle` (trackId или текущий трек),
`lyrics` (path или текущий трек), `toggle`, `next`, `previous`, `subscribe`.
Темы подписок: `track`, `playback`, `queue`, `favorite`; `*` означает все темы.
Повторная подписка заменяет список тем. Состояние подписчиков сравнивается
каждые 100 мс: быстрые промежуточные изменения могут объединяться до последнего
снимка. Историю событий протокол не хранит; для полного актуального состояния
используйте status/queue. Окно queue ограничено 2048 элементами на ответ.

Сервер допускает до 32 одновременных клиентов и до 64 КиБ на входной буфер.
Ответы и уведомления пишет один работник на соединение; медленный читатель
отключается по таймауту записи, не задерживая аудиопоток. Службы завершаются
перед остановкой ядра. Изменение избранного через сокет обновляет БД, библиотеку
и все вхождения трека в очереди; экран избранного обновляется тем же снимком состояния.

Пример запроса с Python:

```python
import json, socket
with socket.socket(socket.AF_UNIX) as connection:
    connection.connect("/tmp/muzon-native/control.sock")
    connection.sendall(b'{"id":1,"method":"status"}\n')
    print(json.loads(connection.makefile().readline()))
```

## Повторный запуск

Один профиль обслуживает один экземпляр: `native.lock` защищает БД и аудиодвижок.
Повторный запуск с тем же `--profile` отправляет запрос через `instance.sock`,
возвращает существующее окно из свёрнутого состояния и завершается успешно.
Другой профиль можно открыть независимо. Сокет активации не зависит от
`MUZON_CONTROL_SOCKET` и MPRIS; при отсутствии подтверждения запуск сообщает
ошибку, не создавая второй движок. После завершения удаляется только собственный
сокет. При доступном трее закрытие скрывает окно; явный пункт «Выйти» завершает приложение.

## Трей

На Linux используется `tray-icon` с KSNI-бэкендом, без GTK и WebView.
Иконка открывает окно; средняя кнопка переключает воспроизведение. В меню:
открыть окно, предыдущий трек, воспроизвести/пауза, следующий трек и выйти.
Подсказка показывает название текущего трека.

Закрытие скрывает окно только после подтверждения регистрации иконки
в StatusNotifierWatcher при наличии активной панели. Воспроизведение продолжается.
Если панель пропала, скрытое окно автоматически возвращается. Без доступного
трея закрытие завершает приложение. «Выйти» в меню, интерфейсе или MPRIS
всегда использует штатное завершение с сохранением сессии и настроек;
ошибка сохранения звука возвращает окно с предложением повторить операцию.
Повторный запуск с тем же профилем также возвращает скрытое окно.

Для отключения трея: `MUZON_TRAY=0`. Регистрация проверяется примерно раз
в секунду; сразу после запуска закрытие может завершить приложение, если
панель ещё не успела подтвердить регистрацию. Оформление меню определяет панель.

## Размер окна

Нативная оболочка сохраняет обычный размер и развёрнутое состояние в
`<profile>/config/window.json`. Запись происходит через 500 мс после изменения
размера и повторяется при штатном выходе; замена файла атомарная. Свёрнутое
состояние и координаты экрана не сохраняются. Окно открывается по центру;
минимальный размер — 800×480. Отсутствующий или повреждённый файл возвращает
размер по умолчанию 1180×760. В развёрнутом состоянии обычный размер сохраняется,
чтобы после восстановления окно не занимало весь экран.

## Автоматическое обновление библиотеки

Сканер следит за добавленными папками, аудио, LRC и известными именами обложек.
Серия изменений объединяется перед пересканированием. Метаданные очереди
обновляются без изменения её позиций. При отключённом диске папка остаётся
в настройках; наблюдение переподключается после возвращения диска.

## Внешний вид

В разделе «Внешний вид» доступны тёмная, светлая и системная темы, свой акцент,
импорт JSON-палитры и автоматическое перечитывание изменённого файла темы.
Системная тема читается через desktop portal. Кнопка «Использовать тему Ryoku»
подключает `$XDG_CACHE_HOME/ryoku/colors.json` с fallback на `~/.cache`.
Это явный выбор источника: произвольная JSON-тема не заменяется автоматически,
конфигурация рабочего стола не записывается. Изменения настроек атомарно
сохраняются в `config/appearance.json`. Ошибка импорта оставляет последнюю
рабочую палитру. Прозрачность окна включается после перезапуска; непрозрачность
настраивается отдельно. Поведение зависит от композитора.

Спектр включается по желанию и обрабатывается только на видимой странице
«Сейчас играет». Используется последний кадр; очередь кадров в UI не копится.
Закрытие в трей также можно отключить настройкой.

## Облако и скробблинг

Отдельный `muzon-services` подключает S3, ListenBrainz и Last.fm без Tauri.
Незаполненные настройки не запускают сетевых запросов и чтения связки ключей.
Синхронизация S3 запускается вручную: сначала настройте endpoint/регион/бакет,
сохраните ключи и проверьте доступ. Передача файлов потоковая, отмена удаляет
незавершённую загрузку. Удаления не синхронизируются. Существующие локальные
файлы не заменяются; облачные объекты с отличающимся размером могут заменяться
локальной версией. Изменения тегов без изменения размера не обнаруживаются
этим сравнением. Поддерживаются аудио, LRC и известные имена обложек.

Для ListenBrainz нужен пользовательский токен, для Last.fm — API key/shared
secret и явное подтверждение в браузере. Ключи хранятся через `secret-tool`,
отдельно для канонического пути каждого профиля. В JSON находятся настройки,
имена аккаунтов и офлайн-очередь, а не секреты. При переносе профиля в другую
папку аккаунты нужно подключить заново. Отключение аккаунта удаляет ожидающие
отправки записи этого аккаунта.

История и передача прослушивания в сервис записываются через транзакционный
SQLite outbox. Офлайн-очередь ограничена 10000 записями на сервис; повторы
отправляются в фоне. Повреждённый файл не перезаписывается пустой очередью:
ошибка показывается в UI, после исправления можно повторить. Прослушивания
без подключённых аккаунтов не отправляются задним числом при их подключении.
При неоднозначном сетевом сбое повторная доставка возможна.

## Установка в Arch Linux

Отдельный пакет `muzon-native` собирается через
[packaging/aur-native/PKGBUILD](../../packaging/aur-native/PKGBUILD):

```bash
cd packaging/aur-native
makepkg -si
```

PKGBUILD использует опубликованный коммит с проверкой SHA-256, а не текущие
незакоммиченные файлы. Он устанавливает `muzon-native`, пункт меню и иконки;
пакет Tauri `muzon` остаётся отдельным. Подробности и обновление версии описаны
в [инструкции пакета](../../packaging/aur-native/README.md).

## Переносимая сборка

```bash
./packaging/native/build.sh release
```

Архив и SHA-256 появляются в `dist/native/`. Сборка не устанавливает приложение.
В архиве `bin/muzon-native` без аргументов использует новый отдельный профиль
`$XDG_DATA_HOME/muzon-native`; явный `--profile DIR` по-прежнему поддерживается.
Системные GStreamer и библиотеки оконного рендера требуются на целевой машине.
Подробности: [packaging/native](../../packaging/native/README.md).
Для явного переноса старой библиотеки предусмотрен `packaging/native/import_profile.py`:
нужны исходные data/config и новый несуществующий каталог назначения. SQLite
копируется через backup с учётом WAL; аккаунты и их очереди не переносятся.

## Границы миграции

Это рабочий нативный плеер; Tauri-версия сохраняется параллельно.
Работа на реальном Wayland/GPU, оконная интеграция Ryoku и полное визуальное
соответствие старому интерфейсу ещё не подтверждены. Альбомы уже представлены
сеткой; подключение палитры Ryoku доступно в настройках внешнего вида.
Между соседними вхождениями
одного и того же файла переход выполняется через EOS, без gapless: старый
движок определяет автопереход по смене URI. Разные файлы используют общий
существующий движок gapless/crossfade.

Демонстрационный режим сохраняет прежнюю синтетическую библиотеку,
таймер прогресса и заглушки обложки/текстов. Звука и файловой сессии в нём нет.

## Проверка

```bash
cargo test --manifest-path crates/muzon-queue/Cargo.toml
cargo test --manifest-path crates/muzon-core/Cargo.toml
cargo test --manifest-path crates/muzon-services/Cargo.toml
cargo test --manifest-path crates/muzon-ui-prototype/Cargo.toml
cargo fmt --manifest-path crates/muzon-ui-prototype/Cargo.toml --check
cargo clippy --manifest-path crates/muzon-ui-prototype/Cargo.toml --all-targets -- -D warnings
```

Для изолированной проверки окна доступен Xvfb:

```bash
ICED_BACKEND=tiny-skia WINIT_UNIX_BACKEND=x11 WAYLAND_DISPLAY= \
  dbus-run-session -- xvfb-run -a \
  cargo run --manifest-path crates/muzon-ui-prototype/Cargo.toml -- --profile /tmp/muzon-headless
```

Реальный режим выводит звук: для автоматических проверок ядра тесты подставляют
GStreamer fakesink; при ручной проверке окна задайте нулевую громкость в тестовом
профиле. Успешный запуск через tiny-skia не подтверждает работу конкретного GPU.

### Проверка прокрутки

Прокручиваемые области используют общий стиль: ползунок 6 px, прозрачная
дорожка и отдельный отступ 16 px справа. Полоса не перекрывает счётчики и
кнопки строк. Визуальная регрессия на 148 треках/исполнителях:

```bash
python3 crates/muzon-ui-prototype/tests/window_smoke.py \
  crates/muzon-ui-prototype/target/release/muzon-ui-prototype --scrollbars
```

Дополнительно нужны ImageMagick и Python Pillow; тест создаёт собственные
Xvfb, D-Bus, аудиофайлы с нулевой громкостью и профиль в `/tmp`.


## Код

- `src/cli.rs` — явный выбор режима и профиля;
- `src/real/` — нативная оболочка над Controller: состояние, команды, представление;
- `src/demo/` — автономная синтетическая демонстрация;
- `src/ui.rs` — геометрия оконных списков, время и выбор строки LRC;
- `../muzon-services` — S3, профильная связка ключей и офлайн-скробблинг;
- `../muzon-core` — библиотека, хранилища, аудиодвижок и фоновый контроллер;
- `../muzon-queue` — независимые алгоритмы очереди и восстановления.
